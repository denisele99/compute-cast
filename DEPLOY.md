# Publishing Compute Cast

The backend runs on **Render** (`render.yaml`), and the frontend runs on **GitHub Pages**
(`.github/workflows/pages.yml`). Both deploy automatically from `main`.

```
GitHub Pages  https://denisele99.github.io/compute-cast/   (static React app)
      │  calls (CORS)
      ▼
Render        https://compute-cast-api.onrender.com          (FastAPI, single instance + 1 GB disk)
```

## 1. Backend on Render (once)

1. Merge the branches into `main` first: both deployments build from `main`.
2. In Render, go to **New**, then **Blueprint**, connect GitHub and pick `denisele99/compute-cast`.
   Render reads `render.yaml` and creates the `compute-cast-api` service.
3. Render asks for the values marked secret. Fill in what you have now and leave the rest empty; you can add
   them later under the service's **Environment** tab.

   | Setting | Where it comes from |
   | --- | --- |
   | `BENCH_DEMO_PASSWORD` | Make one up. People type it in the app to start cloud benchmarks. |
   | `NEBIUS_API_KEY` | Nebius Token Factory API key, used for Recommendations |
   | `NEBIUS_PROJECT_ID` | Nebius console, then the project list, then the project's **⋮** menu, then **Copy project ID** |
   | `NEBIUS_RESULTS_BUCKET_ID`, `NEBIUS_RESULTS_BUCKET_NAME` | Your results bucket (see BENCHMARK.md) |
   | `NEBIUS_S3_ACCESS_KEY_ID`, `NEBIUS_S3_SECRET_ACCESS_KEY` | The results-reader service account's access key |

4. Add the Nebius credentials file: open the service, then **Environment**, then **Secret Files**, then
   **Add**. Name it `credentials.json` and paste the file's contents. The app reads it at
   `/etc/secrets/credentials.json`.
5. Wait for the deploy, then open `https://<your-service>.onrender.com/api/health`. It should show `{"status":"ok"}`.
   Copy the service URL; it's needed in step 2.

`BENCH_SESSION_SECRET` is generated by Render. The benchmark image and the other benchmark defaults are
already set in the code and in `render.yaml`.

**Plan:** `render.yaml` uses the **Starter** plan because the 1 GB disk keeps benchmark sessions, jobs
and allowances across restarts.

On the free plan, delete the `disk` block and set `plan: free`. Everything works, but the benchmark
database resets on every deploy or restart, so keep `BENCH_CLOUD_ENABLED=0` there. The free plan also
sleeps when idle, so the first request after a while takes about a minute.

## 2. Frontend on GitHub Pages (once)

1. On GitHub, open the repository's **Settings**, then **Pages**, and set **Source** to **GitHub Actions**.
2. Open **Settings**, then **Secrets and variables**, then **Actions**, then the **Variables** tab, then
   **New repository variable**: `VITE_API_BASE_URL` = your Render URL from step 1.5, with no trailing slash.
3. Open **Actions**, then **Deploy frontend to GitHub Pages**, then **Run workflow**. It also runs on every
   push to `main` that changes `frontend/`.
4. Open `https://denisele99.github.io/compute-cast/`.

If the Pages address is different (another account or a custom domain), update `CORS_ALLOWED_ORIGINS` on
Render to that origin. Use the origin only, without a path.

## 3. Turning on cloud benchmarks (when the Nebius setup is done)

1. Open a **Shell** on the Render service and run `cd backend && python scripts/check_nebius.py`. Every line
   should say `OK`.
2. Set `BENCH_CLOUD_ENABLED=1` in **Environment**. Render redeploys.
3. In the app, go to **Results**, then **Benchmark**, then **Nebius AI Cloud**. Sign in with
   `BENCH_DEMO_PASSWORD` and run one benchmark.

To switch it off again, set `BENCH_CLOUD_ENABLED=0`.

## Updating

Push or merge to `main`. Render redeploys the backend and the workflow republishes the frontend.
